## Офлайн-проверка

Из корня репозитория выполните следующие команды. `npm ci` загружает зависимости, последующие команды читают файлы и запускают тесты без ключа и подключения к LLM.

```sh
npm ci
npm run check
node artifacts/verify.mjs
npm run eval -- report artifacts/ab
npm run agent -- doctor c91ffcb8-39b9-4e9c-a478-5be184736e50 --state-dir artifacts/doctor
```

`verify.mjs` сверяет порядок и число попыток, ID журнала, SHA-256 входов и двух версий скилла, ссылки доктора на события и наличие скриншотов. Для новых модельных запусков нужен настроенный провайдер. Синтетические проверки принятия, отклонения и отката выполняются через `node --test dist/test/market-gate.test.js` и отделены от двух реальных серий.

## Итоги запусков

В A/B оба варианта получили по 7 корректных артефактов из 15. Поддержка скиллов в этой серии не повысила качество артефактов. Модель пропустила ожидаемую загрузку в 10 попытках B, что видно в журналах и объясняет разрыв между долей верных файлов и полным зачётом. [Сводка A/B](ab/report.md).

Обновление `progress-summary` до `1.1.0` отклонено автоматически. Проверки кандидата не дали полного зачёта ни в одном сценарии, и журнал зафиксировал отказы policy. В активном каталоге осталась `1.0.0`. [Решение](update/decision.json) · [Активная версия](update/active-after-decision.json) · [События рынка](update/market-events.jsonl).

## Чтение журналов

Каждая строка `trials.jsonl` задаёт сценарий, вариант, номер попытки, session/run ID, оценку файла, проверку маршрутизации и инструментов, usage, вызовы и ошибку. Путь к JSONL и результату считается от папки серии. `result.json` раскрывает детали программной проверки. Отдельная [неполная серия](../docs/evidence/ab-incomplete/report.md) сохранена как предварительная проба.
