# Workbench Agent

Терминальный агент на TypeScript для небольшого учебного проекта. Модель выбирает инструменты, а runtime проверяет вызовы, хранит состояние и контролирует бюджет. Из корня репозитория агент по умолчанию работает с контрольным проектом на Python из `workspace/`. Из другой директории отдельная команда `workbench-agent` берёт текущий проект. Второй набор задач посвящён отчётам для учебного трекера.

## Установка

Нужны Node.js ≥ 22.13, npm, Bash и Python 3. Команды рассчитаны на macOS, Linux и WSL.

```sh
npm ci
npm run build
cp .env.example .env
```

### Ollama

В запущенном приложении Ollama скачайте локальную модель с поддержкой tool calling. При установке через CLI поднимите сервер командой `ollama serve` в отдельном терминале.

```sh
ollama pull qwen3:4b
npm run agent -- chat
```

По умолчанию агент использует `http://127.0.0.1:11434/v1/` и `qwen3:4b`. Настройки `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_API_KEY` позволяют использовать другой OpenAI-compatible сервер.

### OpenRouter

Укажите в `.env` параметры профиля OpenRouter, API-ключ и точный ID доступной вам модели с поддержкой tool calling. Для Ollama `OPENAI_API_KEY=ollama` служит заполнителем.

```dotenv
AGENT_PROVIDER=openrouter
OPENAI_BASE_URL=https://openrouter.ai/api/v1/
OPENROUTER_API_KEY=your-key
OPENAI_MODEL=your-provider/your-tool-capable-model
```

Настройки температуры, максимального ответа, таймаута, seed и reasoning effort описаны в [примере окружения](.env.example). Ключи хранятся вне Git.

## Запуск в своём проекте

```sh
npm run build
npm link
cd /path/to/project
workbench-agent chat
```

Также можно передать `--workspace PATH` или вызвать `bin/workbench-agent.mjs` по абсолютному пути. Пример проекта, файлы настройки и правила выбора состояния описаны в [запуске из другой директории](docs/portability.md).

## Диалог и управление запуском

```sh
npm run agent -- chat
npm run agent -- start --mode auto 'Исправь расчёт итоговой стоимости заказа, чтобы тесты проходили. Тесты не меняй. Сам найди нужные файлы, внеси исправление и запусти тесты.'
npm run agent -- resume RUN_ID
npm run agent -- resume RUN_ID --decision approve
npm run agent -- stats SESSION_ID
npm run agent -- tasks RUN_ID
npm run agent -- diff RUN_ID
npm run agent -- rollback RUN_ID
npm run agent -- help
```

В TUI выводятся ожидание модели, поток ответа, запуски инструментов и их результаты. В нижней панели находятся модель, режим, usage и счётчики. Tab переключает Plan, Ask for edits и YOLO, Ctrl+U очищает черновик, а ввод `/` открывает подсказки. См. [клавиши и команды](docs/terminal.md). В диалоге после ответа можно задать уточнение. Для открытия сохранённого диалога используйте `chat --session SESSION_ID`. В TUI доступны `/stats`, `/resume RUN_ID`, `/tasks RUN_ID`, `/diff RUN_ID`, `/rollback RUN_ID`, `/doctor`, `/help` и `/exit`. Режим `safe` запрашивает подтверждение каждого изменения и вызова Bash. При отказе модель получает причину и может продолжить. Режим `auto` выполняет разрешённое policy действие сразу.

### Plan Mode и задачи

```sh
npm run agent -- chat --plan
npm run agent -- start --plan --mode safe 'Исправь расчёт заказа и прогони тесты.'
npm run agent -- resume RUN_ID --decision approve
npm run agent -- tasks RUN_ID
```

До утверждения планирования доступны инструменты чтения. Сохранённый план содержит цель, шаги, зависимости, инструменты, риски, допущения и критерий готовности. Для каждого шага нужно доказательство из фактического успешного tool call этой задачи. Runtime связывает вызовы с активной задачей и запускает следующие задачи после проверки зависимостей. Утверждение плана сохраняет прежний режим подтверждения действий.

### Восстановление и откат

Состояние запусков находится в `.agent/runs/`, журнал JSONL в `.agent/events/`. При перезапуске `resume RUN_ID` показывает остановленный запуск. Для неопределённого вызова `resume` показывает обнаруженные изменения и принимает `retry`, `skip` или `abort`. Если есть обнаруженные правки, укажите `--attribute yes` для их отнесения к запуску или `--attribute no` для фиксации их как внешних. Явный повтор списывает новый бюджет и доступен для инструментов с безопасным повтором.

`diff` показывает создание, изменение и удаление файлов по запуску. `rollback` восстанавливает затронутые им файлы после проверки policy и ожидаемых хешей. Если затронутый файл был изменён внешним процессом, операция останавливается до записи. Обычно стоит начать новый эксперимент с чистой копией `workspace/` или откатить предыдущий запуск.

### Бюджет

На один run действуют лимиты запросов к модели, tool calls, действий с побочным эффектом и байтов результатов. Опции CLI называются `--model-calls`, `--tool-calls`, `--side-effects`, `--result-bytes`. План, исполнение и восстановление расходуют один бюджет. Пачка отклоняется целиком, если заранее известно, что она не поместится по числу действий. Для результатов неизвестного размера runtime передаёт доступный остаток инструменту и отмечает усечение.

## Workspace и policy

| Инструмент    | Аргументы       | Назначение                                                          |
| ------------- | --------------- | ------------------------------------------------------------------- |
| `list_files`  | `path`          | Прочитать список файлов каталога                                    |
| `read_file`   | `path`          | Прочитать текст                                                     |
| `write_file`  | `path, content` | Записать или создать файл                                           |
| `delete_file` | `path`          | Удалить обычный файл                                                |
| `Bash`        | `command, cwd`  | Выполнить разрешённую команду и получить stdout, stderr и exit code |

Рабочий [пример policy](config/policy.json) разрешает `python3 -m unittest -v`, запрещает `rm -rf .`, каталоги `private` и `.git`, защищает `test_order.py` от записи и удаления. Файловые пути относительны к workspace, deny имеет приоритет. Для своей копии используйте `--workspace DIR --policy FILE --state-dir DIR`. Policy и состояние размещаются вне изменяемого дерева.

Bash принимает точные простые команды из allow-list. Аргументы с путями, подстановками, кавычками, конвейерами и перенаправлением отклоняются. Для тестов задан таймаут, ограничен вывод, окружение очищается и установлен `PYTHONDONTWRITEBYTECODE=1`. Разрешённый тестовый код выполняется с правами пользователя, поэтому запускайте агент на доверенной учебной копии без секретов. Снимки охватывают обычные файлы разрешённого дерева, включая исходники и тесты.

## Скиллы и MCP

Скиллы живут в `skills/<имя>/SKILL.md`. Модель получает каталог имён и описаний и сама решает, вызывать ли `load_skill`. Полная инструкция поступает в контекст после вызова. Чтобы добавить каталог к встроенному, запустите агент с `--skills-dir skills --skills-dir DIR`. Ошибки отдельных файлов отображаются в терминале и журнале. Policy действует независимо от текста инструкции. `--no-skills` отключает каталог и загрузчик.

Проектные скиллы можно положить в `WORKSPACE/.agent/skills/<имя>/SKILL.md`. В `/skills` видны статус и оценка размера полной инструкции. Команды `/skills off`, `/skills on`, `/skills disable NAME` и `/skills enable NAME` сохраняют выбор для проекта.

В комплекте три скилла. `open-task-report` помогает собрать отчёт по открытым задачам. `progress-summary` описывает проверку сводки по учебным занятиям. `presentation-design` подходит для запроса о презентации. Запрос «скопируй файл» может выполняться обычными инструментами.

При запуске клиент соединяется по stdio с сервером из [config/mcp.json](config/mcp.json), использует настоящий MCP `tools/list` и `tools/call` и передаёт модели разрешённые схемы. Встроенный сервер трекера читает статический набор задач и публикует `list_tasks` и `get_task`. Для другого совместимого сервера используйте `--mcp-config FILE` и укажите команду, аргументы, таймаут и точные имена разрешённых функций в `allowReadOnly`. Команда запускается относительно папки конфига. У каждого разрешённого инструмента требуется аннотация `readOnlyHint: true`. Доступны структурированные и текстовые ответы. `--no-mcp` отключает соединение. При старте агент делает handshake и запрашивает список инструментов. Просмотр и управление доступны в `/mcp list`, `/mcp test`, `/mcp add ID JSON`, `/mcp remove ID` и `/mcp search QUERY`. Последняя команда обращается к официальному реестру MCP. Поддерживаются stdio и Streamable HTTP. Разрешайте только доверенные серверы с функциями чтения. Доступ к путям, службам и данным нужно ограничивать и в самом сервере.

```sh
npm run agent -- chat --mode auto
```

В первом сообщении можно написать «Составь отчёт по открытым задачам учебного трекера. Сохрани его в open-tasks.md в виде таблицы с ID и названиями». После ответа можно спросить «Сколько задач попало в этот отчёт? Проверь сам файл». Команда `/stats` показывает расход и частоту инструментов и скиллов. В журнале есть ID каждого события, время, session/run ID, аргументы, результаты и отказы.

### Доктор сессии

```sh
npm run agent -- doctor SESSION_ID
npm run agent -- doctor SESSION_ID --state-dir PATH --json
```

Доктор анализирует сохранённые события офлайн. Он показывает расходы по запускам и доступным категориям, частоту загрузок скиллов и выполненных MCP-вызовов. Для каждой находки указывает ID событий, счётчики, возможную причину и действие. Входные и выходные токены берутся из usage API. Пропущенные значения отмечаются как `unknown` или `partial`. Кэш и reasoning показываются отдельно как категории API, уже входящие в соответствующие итоги. [Правила и пример](docs/doctor.md).

### A/B-оценка

[Протокол](docs/evaluation-protocol.md) фиксирует три сценария, эталоны, модель, настройки, порядок и гипотезу. Вариант A запускается без поддержки скиллов. Для B включён каталог. В обоих доступен один и тот же MCP. Каждый trial начинается с чистой копии данных и отдельной сессии. Runner сохраняет журнал, итоговые файлы, проверку результата, routing и вызовы инструментов.

Актуальное состояние эксперимента и способ воспроизвести 18 попыток описаны в [документации eval](docs/evaluation.md). Автоматические тесты проекта работают без локальной модели и без API-ключей.

## Маркетплейс и графический интерфейс

```sh
npm run agent -- market search progress
npm run agent -- market news
npm run gui
```

Маркет поддерживает локальные каталоги и HTTP(S)-источники. Для обновления установленной версии агент запускает сравнение двух версий и сохраняет решение, аргументы и журналы. Автопроверки включаются отдельно. [Маркетплейс и обновления](docs/market.md).

GUI работает через локальный HTTP-сервер. Интерфейс открывается по адресу, который команда выводит в терминал, и поддерживает чат, планы и подтверждения, сессии, настройки модели, скиллы, MCP, доктора, маркет и eval. [Графический интерфейс](docs/gui.md).

На защите используйте [сценарий терминального показа](docs/defense.md) и [воспроизведение уровней 4–10](docs/live-levels.md).
