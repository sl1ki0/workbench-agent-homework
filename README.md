# Workbench Agent

Терминальный агент на TypeScript для небольшого учебного проекта. Модель выбирает инструменты, а runtime проверяет вызовы, хранит состояние и контролирует бюджет. По умолчанию агент работает с контрольным проектом на Python из `workspace/`.

## Установка

Нужны Node.js ≥ 22.13, npm, Bash и Python 3. Команды рассчитаны на macOS, Linux и WSL.

```sh
npm ci
npm run build
cp .env.example .env
```

### Ollama

В запущенном приложении Ollama скачайте локальную модель с поддержкой tool calling. При установке через CLI поднимите сервер командой `ollama serve` в отдельном терминале.

```sh
ollama pull qwen3:4b
npm run agent -- chat
```

По умолчанию агент использует `http://127.0.0.1:11434/v1/` и `qwen3:4b`. Настройки `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_API_KEY` позволяют использовать другой OpenAI-compatible сервер.

### OpenRouter

Укажите в `.env` параметры профиля OpenRouter, API-ключ и точный ID доступной вам модели с поддержкой tool calling. Для Ollama `OPENAI_API_KEY=ollama` служит заполнителем.

```dotenv
AGENT_PROVIDER=openrouter
OPENAI_BASE_URL=https://openrouter.ai/api/v1/
OPENROUTER_API_KEY=your-key
OPENAI_MODEL=your-provider/your-tool-capable-model
```

Настройки температуры, максимального ответа, таймаута, seed и reasoning effort описаны в [примере окружения](.env.example). Ключи хранятся вне Git.

## Диалог и управление запуском

```sh
npm run agent -- chat
npm run agent -- start --mode auto 'Исправь расчёт итоговой стоимости заказа, чтобы тесты проходили. Тесты не меняй. Сам найди нужные файлы, внеси исправление и запусти тесты.'
npm run agent -- resume RUN_ID
npm run agent -- resume RUN_ID --decision approve
npm run agent -- stats SESSION_ID
npm run agent -- tasks RUN_ID
npm run agent -- diff RUN_ID
npm run agent -- rollback RUN_ID
npm run agent -- help
```

В диалоге после ответа можно задать уточнение. Для открытия сохранённого диалога используйте `chat --session SESSION_ID`. В TUI доступны `/stats`, `/resume RUN_ID`, `/tasks RUN_ID`, `/diff RUN_ID`, `/rollback RUN_ID`, `/help` и `/exit`. Режим `safe` запрашивает подтверждение каждого изменения и вызова Bash. При отказе модель получает причину и может продолжить. Режим `auto` выполняет разрешённое policy действие сразу.

### Plan Mode и задачи

```sh
npm run agent -- chat --plan
npm run agent -- start --plan --mode safe 'Исправь расчёт заказа и прогони тесты.'
npm run agent -- resume RUN_ID --decision approve
npm run agent -- tasks RUN_ID
```

До утверждения планирования доступны инструменты чтения. Сохранённый план содержит цель, шаги, зависимости, инструменты, риски, допущения и критерий готовности. Для каждого шага нужно доказательство из фактического успешного tool call этой задачи. Runtime связывает вызовы с активной задачей и запускает следующие задачи после проверки зависимостей. Утверждение плана сохраняет прежний режим подтверждения действий.

### Восстановление и откат

Состояние запусков находится в `.agent/runs/`, журнал JSONL в `.agent/events/`. При перезапуске `resume RUN_ID` показывает остановленный запуск. Для неопределённого вызова `resume` показывает обнаруженные изменения и принимает `retry`, `skip` или `abort`. Если есть обнаруженные правки, укажите `--attribute yes` для их отнесения к запуску или `--attribute no` для фиксации их как внешних. Явный повтор списывает новый бюджет и доступен для инструментов с безопасным повтором.

`diff` показывает создание, изменение и удаление файлов по запуску. `rollback` восстанавливает затронутые им файлы после проверки policy и ожидаемых хешей. Если затронутый файл был изменён внешним процессом, операция останавливается до записи. Обычно стоит начать новый эксперимент с чистой копией `workspace/` или откатить предыдущий запуск.

### Бюджет

На один run действуют лимиты запросов к модели, tool calls, действий с побочным эффектом и байтов результатов. Опции CLI называются `--model-calls`, `--tool-calls`, `--side-effects`, `--result-bytes`. План, исполнение и восстановление расходуют один бюджет. Пачка отклоняется целиком, если заранее известно, что она не поместится по числу действий. Для результатов неизвестного размера runtime передаёт доступный остаток инструменту и отмечает усечение.

## Workspace и policy

| Инструмент    | Аргументы       | Назначение                                                          |
| ------------- | --------------- | ------------------------------------------------------------------- |
| `list_files`  | `path`          | Прочитать список файлов каталога                                    |
| `read_file`   | `path`          | Прочитать текст                                                     |
| `write_file`  | `path, content` | Записать или создать файл                                           |
| `delete_file` | `path`          | Удалить обычный файл                                                |
| `Bash`        | `command, cwd`  | Выполнить разрешённую команду и получить stdout, stderr и exit code |

Рабочий [пример policy](config/policy.json) разрешает `python3 -m unittest -v`, запрещает `rm -rf .`, каталоги `private` и `.git`, защищает `test_order.py` от записи и удаления. Файловые пути относительны к workspace, deny имеет приоритет. Для своей копии используйте `--workspace DIR --policy FILE --state-dir DIR`. Policy и состояние размещаются вне изменяемого дерева.

Bash принимает точные простые команды из allow-list. Аргументы с путями, подстановками, кавычками, конвейерами и перенаправлением отклоняются. Для тестов задан таймаут, ограничен вывод, окружение очищается и установлен `PYTHONDONTWRITEBYTECODE=1`. Разрешённый тестовый код выполняется с правами пользователя, поэтому запускайте агент на доверенной учебной копии без секретов. Снимки охватывают обычные файлы разрешённого дерева, включая исходники и тесты.
