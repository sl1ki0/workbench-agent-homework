# Веб-интерфейс Workbench

После сборки запустите `npm run agent -- gui` или `workbench-agent gui` и откройте URL из терминала. Сервер слушает только `127.0.0.1` на выделенном локальном порту. `Ctrl+C` останавливает сервер. Для тестов достаточно `node --test dist/test/gui.test.js`.

## Что доступно

- **Сессии** возвращают к сохранённому диалогу. В новом диалоге можно выбрать Plan, Ask for edits или YOLO, а затем отправить задачу. Используйте `Ctrl+Enter` или `Cmd+Enter` для отправки многострочного ввода. Панель подтверждения появляется при утверждении плана, запросе разрешения и восстановлении незавершённого действия.
- **Инспектор** обновляет схему запуска по фактическим событиям. Этапы открывают журнал, план и diff. Журнал показывает аргументы и результаты инструментов, идентификаторы и usage. Статистика в нижней строке относится к сессии. Звёздочка обозначает неполные данные провайдера. Кэш входит во входной расход.
- **Модель** выбирается в настройках. Режим thinking передаётся провайдеру, если его поддерживает модель. Интерфейс показывает сигнал thinking и поток открытого текста. API-ключи и адрес провайдера задаются на сервере через окружение или файл из `--env-file`. Изменения имени и режима thinking действуют до остановки сервера.
- **Файлы, план и изменения** показывают разрешённую часть workspace, статус задач и зависимости. Явное подтверждение отката вызывает прежнюю проверку хешей в runtime.
- **Skills и MCP** показывают каталог, примерную стоимость загрузки и доступные инструменты. Переключатели скиллов сохраняются в состоянии. В панели MCP можно проверить подключения, добавить или удалить сервер, а также найти запись в официальном реестре. Адрес из реестра заполняет форму. Подключение требует явного сохранения и списка read-only функций. Активные настройки применяются в следующем запуске.
- **Marketplace** показывает установленные версии, поиск, новинки и обновления. Для обновления выполняется настроенный eval-gate. Расписание включается отдельно. В панели **Оценки A/B** доступны запуск выбранного набора, прогресс и отчёт по сохранённым испытаниям.
- **Доктор** анализирует сохранённую сессию по тем же правилам, что и терминальная команда.

## Хранение и разрешения

Браузер использует один workspace и один каталог состояния, выбранные при запуске сервера. Доступ к API ограничен точным Host, Origin и случайным токеном текущего процесса для POST. Браузерная панель работает через те же правила доступа и ограничения runtime. Просмотр файлов проверяет policy. Каталог проекта `.agent` исключён из редактируемой области и используется для обнаружения скиллов. Разрешения каталога MCP и Marketplace меняются через отдельные команды пользователя. Серверный запуск реальной модели инициируется отправкой задачи, возобновлением, явным запуском оценки или отдельно включённой проверкой обновлений.
