# Терминальный интерфейс

```bash
npm run build
npm run agent -- chat
```

В верхней части терминала остаётся история сообщений и инструментов. Композер показывает текущий ввод, подсказки команд и состояние сессии. В строке состояния видны выбранные модель и режим, каталог скиллов, MCP, количество запросов и токены. `/status` показывает подробности окружения, `/stats` показывает статистику сессии.

## Ввод и режимы

| Клавиша                      | Действие                                                                  |
| ---------------------------- | ------------------------------------------------------------------------- |
| `Enter`                      | Отправить сообщение или подтвердить неполную подсказку команды            |
| `Alt+Enter` или `Ctrl+J`     | Добавить строку в черновик                                                |
| `Ctrl+U`                     | Очистить весь черновик, в том числе текст справа от курсора               |
| `Ctrl+C` при свободном вводе | Очистить черновик. Если поле пустое, выйти                                |
| `↑` / `↓`                    | Выбрать подсказку, переместиться между строками или открыть историю ввода |
| `→` в конце неполной команды | Подставить выбранную подсказку                                            |
| `Tab`                        | Перейти к следующему режиму                                               |
| `Shift+Tab`                  | Перейти к предыдущему режиму                                              |

Введите `/`, чтобы увидеть список доступных команд. `/help` показывает описание управления. При ожидающем решении используйте `/approve` или `/deny`, а для неопределённого действия следуйте подсказке восстановления.

| Режим             | Что произойдёт со следующим запросом                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Plan**          | Агент изучает проект в режиме чтения и ждёт утверждения плана. Утверждённый план выполняется с подтверждениями изменений |
| **Ask for edits** | Агент запрашивает подтверждение для действий с побочными эффектами                                                       |
| **YOLO**          | Агент выполняет разрешённые policy действия без отдельного подтверждения                                                 |

Переключение выбирает режим следующего запуска. Сохранённый запуск сохраняет свои правила и ожидающее решение. Во всех режимах доступны ограничения policy и бюджета.

## Прогресс запроса

После отправки сообщения интерфейс показывает активный запрос, фазу и время ожидания. Когда провайдер присылает текст частями, ответ появляется по мере получения. Вызовы инструментов видны отдельными строками с назначением, результатом или отказом. Для MCP рядом виден сервер. У текстового ответа, скиллов и инструментов разные источники событий.

Команда `/thinking off|low|medium|high|default` задаёт режим рассуждений для следующих запросов. `default` возвращает значение из окружения или настройку провайдера. Возможность регулировать уровень зависит от модели. Когда API сообщает о рассуждении, интерфейс отображает фазу. В журнал попадают рабочие события, ответы и доступные данные usage. Если провайдер не вернул метрику, в интерфейсе отображается `unknown`.

Чтобы увидеть последовательность в терминале, попробуйте `/thinking low`, а затем попросите прочитать файл через инструмент и кратко описать его. Ожидайте индикатор модели, строку инструмента, поступление ответа и обновление счётчиков. Для обычного терминального мастера, потока SSE и тестового сервера есть интеграционная проверка.

```bash
npm run build
node --test dist/test/tui.test.js
```

Для проверки TUI нужен Python 3 с Unix PTY. Тестовый HTTP-сервер контролирует момент отправки фрагментов и выполняется без модели и API-ключей. При перенаправленном вводе или машинном выводе доступен построчный режим. Серия `npm run eval` использует тот же модельный клиент в пакетном режиме без терминальных обновлений.

При выборе `/thinking off` для локального Qwen3 агент также передаёт совместимую инструкцию `/no_think` в запросе модели. Она нужна шаблонам Ollama, которые всегда открывают блок thinking. [Переключатели thinking в Qwen3](https://github.com/QwenLM/Qwen3/blob/main/docs/source/getting_started/quickstart.md).
