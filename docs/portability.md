# Запуск из других проектов

В каталоге Workbench Agent соберите программу и сделайте команду доступной в текущем окружении Node.js.

```sh
npm ci
npm run build
npm link
```

После этого откройте папку своего проекта и вызовите агент.

```sh
cd /path/to/project
workbench-agent chat
```

Без `npm link` можно из той же папки вызвать абсолютный путь к `bin/workbench-agent.mjs` установленной копии. Относительные значения флагов, включая `--workspace`, `--policy`, `--skills-dir`, `--mcp-config` и `--env-file`, разрешаются от текущей папки.

Команда из корня репозитория по умолчанию открывает учебный `workspace/` и сохраняет историю в `.agent/` репозитория. Из другой папки рабочей областью становится текущий проект. Состояние внешнего проекта хранится за его пределами, обычно под `${XDG_STATE_HOME:-$HOME/.local/state}/workbench-agent/projects/`. Оно привязано к каноническому пути проекта. `--state-dir` позволяет указать другой каталог вне workspace.

Policy, встроенный каталог скиллов, MCP и профиль модели по умолчанию берутся из установленной копии агента. Для своей конфигурации выбирайте доверенные файлы и передавайте пути явно. `--env-file PATH` задаёт отдельный профиль модели. При обычном запуске используется `.env` установленной копии. Можно также передать параметры модели через переменные среды.

## Скиллы проекта

Добавьте `SKILL.md` в `.agent/skills/<имя>/` внутри проекта. Также поддерживается `.agent/<имя>/SKILL.md`. Встроенные и пользовательские каталоги просматриваются раньше проектных. При одинаковых именах действует первое определение. Символические ссылки в проектном каталоге не раскрываются.

Оценка размера скилла вычисляется как число байт UTF-8 в инструкции, делённое на четыре с округлением вверх. Для точного учёта расхода запроса используйте usage API. Отключение скрывает описание и инструкцию от модели и сохраняет запись в инвентаре терминала.
